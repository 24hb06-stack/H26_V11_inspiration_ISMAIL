## Démarche / Choix techniques

### HTML
Pour moi, le HTML a été assez facile à utiliser. J’ai utilisé des balises sémantiques comme `<header>`, `<main>`, `<footer>`, `<nav>` et `<section>` pour organiser le contenu, ainsi que des balises de base comme `<div>`, `<h1>`, `<h2>`, `<h3>`, `<p>`, `<a>`, `<img>` et `<form>` pour construire les différents éléments du site. Pour les (class), je les ai nommées de la même façon que les sections dans Figma. Par exemple, si la première section s’appelait `hero` dans Figma, j’ai nommé la classe `hero` ex:`<main class="hero">`. Cela m’a permis de travailler plus facilement et de retrouver rapidement chaque section dans le code. Il fallait aussi que j’utilise des commentaires HTML comme `<!--Section de Navbar-->` pour mieux comprendre dans quelle section je me trouvais et pour faciliter la lecture et l’organisation du code. Cela était obligatoire, comme pour BEM, qu’il fallait également utiliser pour nommer correctement les classes pour être plus propre et bien organiser.

### CSS
Le CSS a été la partie la plus difficile du projet pour moi. Contrairement au HTML, où tout était relativement simple, le CSS m’a demandé beaucoup de réflexion pour aligner correctement les éléments et obtenir le rendu souhaité.  
J’ai utilisé des (variables CSS) pour gérer les couleurs, les typographies et les espacements, même si certaines ne fonctionnaient pas toujours comme prévu.  
J’ai appliqué la méthodologie **BEM** pour nommer mes classes, ce qui m’a aidé à garder le code organisé. Par exemple : `navbar` `navbar__links`, `btn--primary`, etc.  
Pour certaines mises en page complexes, j’ai eu recours à **l’IA (Gemini)** afin de mieux comprendre comment aligner correctement les éléments et résoudre certains problèmes. Cela m’a permis de ne pas abandonner le projet malgré les difficultés rencontrées (J'en parle plus dans le section IA).  
Malgré tout, j’ai fait tout le code moi-même et l’IA n’a été utilisée que comme support pour comprendre et corriger certaines parties, pas pour créer le code. Pour celle que je n'étais pas capable de réussir à bien structurer j'ai abondonner et j'aimerai revoir le code corriger en comment je pourai les reussir afin d'apprendre au futur.

### Flexbox
Il fallait utiliser Flexbox dans presque toutes les parties de mon site. Chaque section comportait différents outils de Flexbox, comme `display: flex`, `flex-direction`, `justify-content`, `align-items`, `gap`, et parfois `flex-wrap`, pour aligner et espacer correctement les éléments. Pour certaines propriétés de Flexbox, j’avais oublié exactement leur rôle ou comment elles fonctionnaient. J’ai donc utilisé l’IA pour me rappeler à quoi elles servaient et comment les appliquer correctement dans mon code.
Mais pour être honnête, la plupart du temps, je prenais le CSS du Figma et je le mettais directement dans la classe correspondante. Parfois, cela ne fonctionnait pas et les éléments ne s’alignaient pas correctement. Il fallait alors que j’enlève certaines parties Flexbox du CSS ou que j’utilise l’IA pour comprendre pourquoi le code ne fonctionnait pas et comment résoudre le problème.

### Utilisation de l’IA
